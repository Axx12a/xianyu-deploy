# 部署步骤

## 一、准备

### 环境要求

| 项 | 要求 |
|---|---|
| Docker | Docker Desktop（含 Compose v2） |
| 磁盘 | 镜像约 8.7 GB，加数据建议预留 20 GB |
| 内存 | 给 Docker 至少 4 GB |

### 镜像来源

所有镜像来自阿里云容器镜像服务 `registry.cn-shanghai.aliyuncs.com/zhinian-software/`，
国内拉取速度正常。共 6 个：

```
xianyu-mysql:8.0            1.1 GB
xianyu-redis:7-alpine        58 MB
xianyu-backend-web:latest   3.07 GB
xianyu-websocket:latest     2.69 GB
xianyu-scheduler:latest     2.42 GB
xianyu-frontend:latest      100 MB
```

## 二、配置 .env

```bash
cp .env.example .env
```

**必须改的三项**：

```
MYSQL_ROOT_PASSWORD=改成你的强密码
MYSQL_PASSWORD=改成你的强密码
REDIS_PASSWORD=改成你的强密码
```

> ⚠️ 这三个密码**只在数据库首次初始化时生效**。
> 库建好之后再改 `.env` 不会改密码，得进 MySQL 用 SQL 改。
> 所以第一次启动前一定要改掉默认值。

其余项保持默认即可。可选调整：

- `FRONTEND_PORT`：默认 9000，冲突就改
- `ENABLE_REMOTE_ADS` 等三项：默认已关（不向 upstream 服务器拉取广告和公告）
- `SQL_ECHO`：排查问题时设 `true`，会打印每条 SQL

## 三、创建挂载目录

```bash
mkdir -p xianyu_auto_reply/mysql/data
mkdir -p xianyu_auto_reply/redis/data
mkdir -p xianyu_auto_reply/logs/backend_web
mkdir -p xianyu_auto_reply/logs/websocket
mkdir -p xianyu_auto_reply/logs/scheduler
mkdir -p xianyu_auto_reply/static
mkdir -p xianyu_auto_reply/backups
mkdir -p xianyu_auto_reply/browser_data
```

Windows 用 `启动系统.bat` 会自动跳过这一步。

## 四、启动

```bash
docker compose -f docker-compose.deploy.yml pull
docker compose -f docker-compose.deploy.yml up -d
```

启动顺序由 `depends_on` + 健康检查控制，是串行的：

```
mysql (healthy) → redis (healthy) → backend-web (healthy)
              → websocket (healthy) → scheduler
              → frontend
```

首次启动 MySQL 初始化约需 30 秒，整体 1~2 分钟。

## 五、验证

```bash
docker compose -f docker-compose.deploy.yml ps
```

| 容器 | 期望 |
|---|---|
| xianyu-mysql | healthy |
| xianyu-redis | healthy |
| xianyu-backend-web | healthy |
| xianyu-websocket | healthy |
| xianyu-scheduler | healthy |
| xianyu-frontend | **unhealthy 是正常的**（见下） |

各服务健康端点：

```bash
curl http://localhost:8089/health
curl http://localhost:8090/health
curl http://localhost:8091/health
```

### 前端显示 unhealthy 是误报

前端镜像内置的健康检查是：

```
wget --no-verbose --tries=1 --spider http://localhost:80/
```

但那个 nginx 镜像里**没有装 wget**，所以探测必然失败，显示 unhealthy。
实际访问 `http://localhost:9000` 是 HTTP 200，服务完全正常，可以忽略。

## 六、首次登录

打开 `http://localhost:9000`：

```
用户名  admin
密码    admin123
```

登录后会有一个免责声明弹窗，勾选同意即可。

**登录后立刻改密码**：后台「个人设置」。

> 默认密码是后端首次建库时写进 MySQL 的，改 `.env` 没用，只能在后台改。

## 七、接入闲鱼账号

三种方式，推荐优先级从高到低：

### 1. Cookie 导入（最稳）

在你自己的浏览器里正常登录闲鱼，然后：

1. 打开 `https://www.goofish.com` 并确认已登录
2. F12 → **Network** → 刷新页面
3. 点任意一条发往 `goofish.com` 的请求
4. **Headers → Request Headers → 找到 `Cookie:` 那一行**，复制整行的值

   > 用这里而不是控制台 `document.cookie`，因为 `cookie2`、`unb` 等
   > 关键字段是 httpOnly 的，控制台取不到。
5. 回系统：账号列表 → 编辑该账号 → 粘贴到 Cookie 框 → 保存

### 2. 扫码登录

「扫码添加账号」→ 用闲鱼 App 扫码 → 手机确认。

如果账号被风控要求人脸验证，登录弹窗会切换成一张**新的二维码**，
**用手机扫那张新码**完成刷脸（不是等手机弹窗——闲鱼不会主动推送）。

### 3. 账号密码

后端支持，但**需要容器里装有系统版 Google Chrome**（上游写死了
`channel='chrome'`），而镜像里只有 Playwright 自带的 Chromium，
所以这条路径在默认镜像里会直接报错：

```
BrowserType.launch_persistent_context:
Chromium distribution 'chrome' is not found at /opt/google/chrome/chrome
```

要用的话得改造镜像加装 Chrome。另外这条路径会把**账号密码明文写入数据库**。

## 常见问题

**Q：改了前端代码看不到效果？**

本仓库的 nginx 配置已对 `index.html` 禁用缓存。如果你删掉了那处挂载，
就需要 `Ctrl + Shift + R` 强刷，普通 F5 可能仍用缓存。

**Q：容器重启后账号显示"需重新扫码"？**

通常是闲鱼 Token 过期。系统会自动尝试刷新；刷新失败说明登录态已失效，
需要重新导入 Cookie 或扫码。

**Q：某个账号一直"监听异常"？**

看 websocket 日志。如果是 `gaierror: Name or service not known`，
那是网络/DNS 瞬时故障导致连续重试失败——**在账号列表点「暂停」再点「启用」**
即可重启该账号的任务，不用重启容器。

**Q：怎么更新到新版本？**

```bash
docker compose -f docker-compose.deploy.yml pull
docker compose -f docker-compose.deploy.yml up -d
```

数据库结构变更由 backend-web 启动时自动迁移。
更新前建议先备份 `xianyu_auto_reply/mysql/data/`。
